# RCA — gemstone-makeover redeploy (run 3906bbfb-4022-4d4a-8608-27caa4931d18)

## Outcome
Deploy FAILED at `deploy_k8s` / health_check. The app is NOT down — the failed run was never promoted, so the previous healthy run (`dd745bcc`, deployed 2026-09-02) is still live and serving `https://gemstone-makeover.emergent.host`.

## Symptom
Rollout never became ready. Both pods (`...-mjbfz`, `...-bcfs9`) CrashLoopBackOff; startup probe `GET /health` → 503 / connection refused because the FastAPI backend exits on import before nginx can proxy to it.

## Root cause (verified from logs)
Backend crashes at import time:

```
RuntimeError: CORS_ORIGINS must explicitly list trusted website origins
  File "/app/backend/server.py", line 2304, in <module>
    raise RuntimeError("CORS_ORIGINS must explicitly list trusted website origins")
Backend died, shutting down nginx...
```

The current source (server.py line ~2304) added a hard guard that **refuses to start unless `CORS_ORIGINS` is set to an explicit list of trusted origins** (it rejects empty / wildcard `*` / placeholder values).

`list_secrets` on the live run shows `CORS_ORIGINS` IS present and `is_empty=false` — so a value exists, but the app's new guard rejects it (the stored value is almost certainly `*` or a preview placeholder, not an explicit origin list). Value itself is KMS-sealed and not readable by tooling, so the exact string is inferred, not seen.

## Why a plain redeploy will NOT fix it
On redeploy, new `.env` keys from preview are picked up but **pre-existing deployment secret values are NEVER overwritten**. `CORS_ORIGINS` already exists in the deployment secret store, so even if preview `backend/.env` now holds a correct value, the stale/rejected production value persists and the boot guard fails identically. This is why re-firing the pipeline as-is is futile.

## Fix (user / E1 action — not a manifest or source fix)
Update the value of `CORS_ORIGINS` in **Deployment Panel → Secrets** to an explicit, comma-separated list of the app's real origins, then redeploy. Suggested value based on this deployment's URL + linked domains:

```
CORS_ORIGINS=https://gemstone-makeover.emergent.host,https://essentialgemstones.com,https://www.essentialgemstones.com
```

(Confirm the exact origins the frontend calls from; do not use `*`.)

After saving the corrected value in the Secrets tab, redeploy. The backend will then pass the guard and boot.

## Not reproduced in sandbox
The eph sandbox injects no app secrets, so this env-var guard cannot be exercised there. Diagnosis is from the failing run's logs + pod events + the live-run secret metadata — reported as diagnosed, not reproduced.
